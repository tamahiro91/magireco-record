# MagirecoRecord

※本リポジトリは個人制作の非公式ファンツールです。パチスロ「マギアレコード」の公式・関連団体とは関係ありません。

パチスロ「マギアレコード」の実戦データを記録・管理するための個人用Webアプリです。スマホのブラウザからそのまま使えます。

**アプリを開く：** https://tamahiro91.github.io/magireco-record/

## 主な機能

- 来店記録の一覧・詳細の2画面構成、ダーク配色のモバイル最適化UI
- 店舗名・日付・台番号・メモの記録、来店回数と当選回数の集計、店舗名での検索
- ゲーム数・ポイント・AT初期ゲーム数、BIG/みたま/各種CZなど当選パターンの記録
- atゲーム数（AT初期ゲーム数＋うぃチャンス上乗せ＋at継続40ゲーム）の自動集計
- 設定示唆情報（ビッグ終了後のボイス・画面パターン、エンブリオ当選契機、ストーリー順番示唆など）の記録
- 途中から座った場合の引き継ぎ情報（回転数・BIG・at・at初当たり回数）と引き継ぎ込み確率の表示
- スイカ/CZ/CZ成功のタップカウンター、投資枚数・回収枚数の入力による差枚（収支）の自動計算
- カレンダー画面：日別の来店件数・差枚の表示、店舗別収支（今月/全期間、差枚順/回数順で切替可）
- 記録のドラッグ並び替え・削除
- JSONエクスポート/インポート、同期コードによるデバイス間データ共有（Firebase Firestore）

## 使い方

インストール不要、ログイン不要です。上記のリンクをスマホやPCのブラウザで開くだけで利用できます。

1. **来店を追加** — 一覧画面右下の「＋」から店舗名・日付などを入力して保存します。
2. **記録を追加** — 来店の詳細画面を開き、右下の「＋」からその日1回分の記録（ゲーム数・当選結果・設定示唆など）を追加します。1来店につき何回でも追加できます。
3. **詳細画面を確認** — 通常総ゲーム数・atゲーム数・各当選確率・差枚（収支）などが自動集計されます。回収枚数を入力すると差枚がその場で計算されます。
4. **カレンダーで振り返る** — 一覧画面の📅ボタンから月別カレンダーを開けます。日ごとの件数・差枚に加えて、店舗別の収支や回収率も確認できます。
5. **バックアップ・同期** — 画面右上の「⋯」から、JSONの書き出し/読み込みや、複数端末でデータを共有するための同期コードを設定できます。

## FAQ

**Q. データはどこに保存されますか？**
A. 基本的に端末内（ブラウザのlocalStorage）にのみ保存されます。同期コードを発行・入力した場合のみ、クラウド（Firebase Firestore）にも送信されます。

**Q. 複数の端末で同じデータを使いたい**
A. 「⋯」→「新しい同期コードを発行」でコードを発行し、もう一方の端末で「他の端末で発行したコードを入力して同期」からそのコードを入力してください。

**Q. 機種変更などでデータを移行したい**
A. 「⋯」→「JSONを書き出し」で記録データをファイルとして保存し、新しい端末で「JSONを読み込み」から読み込んでください。読み込みは既存データへの追加（マージ）で、上書きはされません。

**Q. データを削除してしまう操作はありますか？**
A. 来店記録・個別の記録・うぃチャンスなどの各項目には削除ボタンがあり、いずれも確認ダイアログが表示されます（記録一覧のドラッグハンドルは、タップすると削除確認、ドラッグすると並び替えになるので注意してください）。

最も注意が必要なのは同期関連です。同期コードを入力した際、端末側・クラウド側の両方に既にデータがある場合は確認が出ますが、どちらを選んでも**マージはされず、片方のデータで もう片方が丸ごと上書き**されます。また、同期を開始した後は他の端末での削除がリアルタイムでこの端末にも反映されます。大事なデータがある場合は、同期前にJSONで書き出しておくことをおすすめします。

なお、同期の解除（「同期を解除」ボタン）自体はクラウド側の共有を止めるだけで、端末内のデータは消えません。

**Q. 差枚（収支）の「換金ギャップ」とは？**
A. スロットの実際の投資・回収は現金と等価交換所での交換レートにズレ（ギャップ）が生じることがありますが、このアプリの差枚計算はそうした換金レートの違いを考慮していません。あくまで投資枚数と回収枚数（コイン単位）の差分です。

**Q. データの記録にどれくらいストレージ容量を使いますか？**
A. 記録1件あたりの目安は以下の通りです（内容の濃さによって変動します）。

| 内容 | サイズ |
|---|---|
| 軽い記録（ゲーム数のみ） | 約0.3KB |
| 標準的な記録（当選＋うぃチャンス1件＋at終了画面など） | 約0.5KB |
| かなり作り込んだ記録（エンブリオ＋ドッペル＋うぃチャンス複数＋メモ入り） | 約1.1KB |

1来店＝平均3記録として試算すると、来店件数ごとの合計サイズはこの程度になります。

| 来店件数 | サイズ |
|---|---|
| 100件 | 約0.2MB |
| 1,000件 | 約1.9MB |
| 5,000件 | 約9.5MB |

週3回×1年通っても（156来店）合計300KB程度です。ブラウザのlocalStorage上限は1オリジンあたり5〜10MBが目安なので、よほど長期間・高頻度で使い込まない限り容量を心配する必要はありません。同期を使う場合はFirebase Firestore側にも同じデータが送信されますが、無料枠（1GB）に対して十分小さい容量です。
